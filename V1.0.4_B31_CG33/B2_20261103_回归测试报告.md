# 数显轨距尺 B2 第二批回归测试报告

**版本**：`V1.0.1.zip`（B1 基线）→ `V1.0.2_B2`  
**测试日期**：2026-11-03  
**结论**：主控模拟 HAL/EEPROM 条件下的 GCC 主机端单元回归测试 **41 项断言通过**；倾角板模拟 USART/SysTick 条件下 ACK 与周期测试通过。**尚未 Keil 编译/烧录/真机验证。**

## 一、运行环境与测试对象

- 系统：容器 Linux；编译器：`gcc`/`cc`，C99。
- 选项：`-O1 -g -Wall -Wextra -fsanitize=address,undefined -fno-omit-frame-pointer`。
- 主控实际待测源文件：`STM32L151/Software/src/usart_code.c` 和 `agreement_code.c`；使用项目原有头文件，替换的仅是供主机模拟使用的 STM32 HAL 与 EEPROM 外设函数。
- 倾角板实际待测逻辑：从 `QINGJIAOBAN/USER/main.c` 和 `USER/stm32f10x_it.c` **直接抽取**实际的 `USART1_IQRN`、`getAdd`、主循环 ACK 处理片段、`SysTick_Handler`，配合主机模拟寄存器运行。
- 测试代码及入口：`B2_HOST_TESTS/run_master_tests.sh`、`B2_HOST_TESTS/test_main.c`、`B2_HOST_TESTS/test_qing.py`。该文件夹不参与 Keil 编译。

## 二、主控回归用例

| 用例 | 输入或场景 | 期待结果 | 结果 |
|---|---|---|---|
| M01 | UART 初始化 | UART1/2 均持续处于接收状态；未初始化 UART3 | 通过 |
| M02 | 上电前未收到传感器帧 | `Sensor_Data_Is_Fresh()` 为 0 | 通过 |
| M03 | 13 字节合法轨距、超高、温度帧 | 更新对应变量并返回 7 字节 ACK | 通过 |
| M04 | 两帧连续到达，前台尚未处理 | 第一帧保持不变，第二帧丢弃并计数 | 通过 |
| M05 | 收包但尚未执行前台轮询 | 绝不在 ISR 中发送 ACK | 通过 |
| M06 | 传感器温度负数（最高位为1） | 正确完成 float 位模式重组，无 UBSan 问题 | 通过 |
| M07 | 传感器校验和被篡改 | 不解析、不 ACK；坏帧计数增加 | 通过 |
| M08 | 传感器数据时间超 1500ms | `Sensor_Data_Is_Fresh()` 变为 0 | 通过 |
| M09 | UART2 合法握手 | 返回 `0x81`，7 字节正确响应 | 通过 |
| M10 | UART2 校验和错误 | 不响应、不进入业务 | 通过 |
| M11 | UART2 写密码负载只有3字节 | 返回 `0xC3`，EEPROM 写次数仍为0 | 通过 |
| M12 | UART2 写密码负载4字节 | 返回 `0x83`，模拟 EEPROM 写次数为4 | 通过 |
| M13 | UART2 清空记录 `0x05` | 返回 `0xC5`，不写/清 EEPROM | 通过 |
| M14 | UART2 单条记录查询 | 两字节索引与其后15字节记录完整返回 | 通过 |
| M15 | UART2 全部记录查询 | 记录数、总长度、累计校验及末尾符合协议 | 通过 |
| M16 | 256字节 UART2 完整帧，负载中含 `0D 0A 5A` | 依长度组帧，不误判中途帧尾 | 通过 |
| M17 | 多帧连续写入单帧邮箱 | 不覆盖待处理帧，显式累计丢帧 | 通过 |
| M18 | EEPROM 记录数量损坏（超100） | 不执行大规模读取；返回 `0xC9` | 通过 |
| M19 | UART2 长度字段超上界 | 在第4字节识别错误并可接收后续合法帧 | 通过 |
| M20 | UART2 半帧中途出现 IDLE | 丢弃半帧并重新同步；后续正常帧可用 | 通过 |
| M21 | HAL UART 接收错误回调 | 自动恢复重新接收，不破坏已完成缓存 | 通过 |
| M22 | 50,000 字节混合噪声/随机数据 | ASan/UBSan 不报越界；接收状态保持有效 | 通过 |
| M23 | 整体路径中断阻塞发送监控 | ISR 中 `HAL_UART_Transmit` 调用次数为0 | 通过 |

主控测试记录（实际执行）：

```text
B2 HOST: PASS 41 assertions; UART1 bad=181 dropped=1; UART2 bad=3; 50,000 noise bytes; no IRQ TX
```

这里的坏帧计数包含专门注入的异常和随机噪声，不代表真实硬件故障率。

## 三、倾角板回归用例

| 用例 | 输入或场景 | 期待结果 | 结果 |
|---|---|---|---|
| Q01 | SysTick 499 次 | 尚未置位 `send_en` | 通过 |
| Q02 | 第 500 次 SysTick | 置位一次 `send_en` 并将计数归零 | 通过 |
| Q03 | 合法 `OK` ACK | `rx_ok=1`，正确消费 ACK，不触发发送 | 通过 |
| Q04 | 合法错误状态 ACK | 计入错误应答次数，不触发发送 | 通过 |
| Q05 | 错误校验和 ACK | 被丢弃，`rx_ok` 不置位 | 通过 |
| Q06 | 再次 500ms 到期 | 由 SysTick 独立产生发送事件 | 通过 |
| Q07 | 120,000 字节噪声 | 无 ASan/UBSan 越界 | 通过 |
| Q08 | 截断 ACK 后出现新帧头 | 按 `0x5A` 重新同步并收完整合法 ACK | 通过 |

倾角板测试记录（实际执行）：

```text
B2 QING: PASS; ACK ok=3 error=1, 120,000 noise bytes, 500ms scheduler
```

## 四、复现方法

在包含 `STM32L151/`、`QINGJIAOBAN/`、`B2_HOST_TESTS/` 的完整 B2 项目目录下执行：

```sh
sh B2_HOST_TESTS/run_master_tests.sh
python3 B2_HOST_TESTS/test_qing.py
```

需要安装本机 `cc/gcc`、Python 3，以及可用的 AddressSanitizer/UndefinedBehaviorSanitizer。测试脚本不会擦除、烧写 MCU 或访问真实 EEPROM。

## 五、未覆盖与限制

1. 本报告是**主机端行为测试**，不是 Keil 工程完整编译/链接结果；硬件引脚、NVIC 优先级、实际 USART 空闲中断延迟尚待验收。
2. 单帧邮箱有意舍弃前台忙时的后续帧，未实现全速无损数据队列。观察 `dropped_frame_count` 后再决定是否需要 FIFO/DMA。
3. 长时间运行、示波器/逻辑分析仪、极限波特率噪声、串口拔插/干扰、主控上电/复位及 EEPROM 写保护均未通过实物验证。
4. OLED 仍可能显示最近一次合法测量值，通信超时由 `Sensor_Data_Is_Fresh()` 提供判定，但 UI 尚未接入明显的“断线/数据无效”提示。
5. EEPROM 型号与地址冲突、超高系数初始化、查照护背实时计算等**均未修复**，不能据此声称测量精度验收通过。

**最终状态：B2 源码与主机测试完成，Keil 编译 / 实物通信 / EEPROM 数据安全 / 测量准确性仍需现场验证。**
