# HXGT CG34-RC2 · 2026-11-20 · 源码审查及台架候选版

基于 CG34-RC1（`2fc4b59`），原始上游基线 `13e80b20b9d5c259a0e4bf6ee05dca3e5aab9ca7`。本包是两个完整的 Keil 工程、Git 提交补丁与主机测试记录。没有新版 HEX，也不含旧编译产物。**两块板必须成套升级；仅限台架。未做 Keil 链接和实机检定，不能用于在役轨道检修、放行或质量签认。**

## 主动读源码发现的缺陷与证据

| 编号 | 原问题 | 修改与验证 |
|---|---|---|
| RC2-01 | `agreement_code.c` 在读完所有历史记录前就发成功帧头；第 2 条读失败时留下半帧，再接错误帧。原同步循环还会长期占用测量主循环。 | 复现：在第 2 条注入 I²C/读错误，RC1 “只能收到完整 C9 帧”断言失败。改成最多 1507 字节的完整暂存，主循环每次最多读一条或发 128 字节；读失败只发完整 C9，TX 失败停止残帧不再拼错误帧，数据采集在各片之间继续。正常帧格式、校验与命令号不变。测试覆盖满 100 条、读取失败、中途 TX 超时、重试及 UART1 仍处理测量数据。真实 PC 客户端仍需验证首包及分片超时。 |
| RC2-02 | 倾角板 ADS1110 的旧接口无法区分读失败和上次 ADC；掉线、配置异常或无新转换时，旧数据可被当成正在测量。末字节 ACK 和位时序也有问题。 | 有效状态、转换就绪和最长 300 ms 无新样本检查；收到 NACK/错误配置/负码时立即无效；取到真正的新转换才更新原有 0.5 滤波，恢复首样本重新初始化。无效 GJ 字段使用 `0xFFFF`，不改 13 字节格式；新主板对 GJ 报 NO SENSOR，不把这一故障当成整台倾角板离线，正常 CG 仍可在 OLED 更新。保留原始 15 SPS 配置；补明 ADC161 上电 CS/CLK 空闲电平，采样时钟与位序不改。模拟测试覆盖故障和恢复；[TI ADS1110 数据手册](https://www.ti.com/lit/ds/symlink/ads1110.pdf)。**原主板不认识 0xFFFF：不能只刷新的倾角板。** |
| RC2-03 | 超高流程可在某些采点时使用坏温度；轨距/查护可在过期 ADC 上标定，并在 EEPROM 写入前或失败后显示“成功”。 | 对相应采点或保存检查传感帧新鲜度、ADC 标志和温度；页面显示暂存值，只有提交已经验证才显示成功。故障时不推进采点或提交状态，提示故障。查护测量本身仍未实现，本次未启用。 |
| RC2-04 | 校准零点正反读数交叉时，旧算法用排序后零位分支边界，却用未排序零位作斜率锚点；原码在越过边界时会产生跳变。 | 复现：用交叉的 500 / 0 AD 零位及 ±12000 AD 参考，刚越零带的 -1 AD 断言在 RC1 失败（旧式计算约 7.2 mm）。外侧线段现在与相应零带边缘连接，保持两端 ±180 mm 锚点，不改温补系数和 3 AD 滞回。测试覆盖 0 带两边连续性与两端不变；旧有正常排序标定物理精度仍以检定器验证。 |
| RC2-05 | 首次保存记录时如果元数据页中途断电，旧版可把整个空日志判为损坏；若提交标记已经写到芯片但 I²C 回读失败，旧版重试可覆盖一个实际已提交的记录。 | 首次 torn-write 只有在与已知序列 1 的未提交字节前缀逐字节相符、备用槽空白、后续记录区全擦除、校准有效时才按空日志读出；开机不改写此元数据。写前验证目标槽已失效；提交结果不确定则封锁对应存储写入，重启/重新加载后再决定。覆盖元数据写入的 64 个断电位置，以及标记实际写入但传输报错、最后回读失败等。原 EEPROM 地址、记录编码和迁移开关未改变。 |

## 复查结论和未验证项
- 两个 MCU 的 C 源码用实际工程头文件与宏做主机语法检查；独立 UART/EEPROM/界面/数学/传感器故障测试均通过，见 `release/host-test.log`。源码回归边界不等于整机合格。
- 没有改温度补偿常数，也没有把 2 秒软件模型当成实机。仍须确认传感器型号与 I²C/SPI 波形、ADC161 时钟及采样间隔，做夹具阶跃、温循与断电实测。旧版 1500 ms 串口失联保护是另一指标，不等于达到 2 秒内稳定。
- PC 工具若在批量读取期间发送多个并发命令，设备仍只有一个 UART2 接收邮箱，可能丢弃后续命令；按一次一个请求验证即可。不假定 PC 产品的首字节或分片超时策略。
- UART2 口的既有本地维护命令没有新增认证；如对非受控外设开放，需要单独设计权限和兼容性，不要把物理 UART 直接暴露给不可信设备。量程外 CG 数字仍保留旧版诊断语义，不视为计量合格值；查护页仍为 NOT READY。
- 建议顺序：备份两板固件、EEPROM 校准及历史 → 两板分别 Keil Rebuild All → 确认新增 RAM 使用（1507 字节批量暂存）和 Flash 链接报告 → 成套台架烧录 → ADS 拔插、历史 100 条读出、EEPROM 分阶段断电、交叉零位验证 → 按 RC1 台架清单复测 2 秒和温漂。故障时回退两块板，不混刷。对旧机 EEPROM 不进行擦除或迁移。
