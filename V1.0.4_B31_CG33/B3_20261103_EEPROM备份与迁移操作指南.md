# B3 现场EEPROM数据保护与一次性迁移说明（务必先看）

> 本文件是防数据损坏流程说明，**不构成让固件在首次启动就写新区的授权**。已确认芯片为AT24C512，具体子型号/地址引脚/WP仍须在实物上核实。

## 1. 备份先行

1. 用编程器/现场成熟的只读方式，导出AT24C512完整`0x0000..0xFFFF`共65536字节，保存为`eeprom_before_b3_read1.bin`。
2. 不更改芯片，第二次独立导出`eeprom_before_b3_read2.bin`。
3. 对比两个文件长度、SHA256与字节内容，必须完全一致，否则暂停升级，先查I2C线路及供电。
4. 将原始文件存档在设备之外，不要只存在原芯片上。**不要调用旧版本`AT24C512_Check()`来验证EEPROM，因为旧函数写地址0x0000。**
5. 在电脑运行：
   ```sh
   python3 B3_HOST_TESTS/inspect_dump.py eeprom_before_b3_read1.bin --json inspect_before.json
   ```
   报告会指出B3新槽、旧校准字节、旧计数冲突点。报告不保证猜出已损坏的温度和ADC原值。

## 2. 第一次刷入 B3（保持所有服务开关关闭）

在`STM32L151/Software/inc/App_Eep.h`确认：

```c
#define EEP_B3_SERVICE_ENABLE_LEGACY_CAL_UPGRADE  0
#define EEP_B3_SERVICE_IMPORT_LEGACY_COUNT        0
```

在 Keil 完整Rebuild新主控固件并烧录。开机后在Watch观察：

- `B3_Eeprom_Boot_OK == 1`仅说明I2C/当前存储读通，**不代表精度已校准**。
- `Eep_Get_Storage_State() == 2`代表旧参数锁定，禁止新参数写入；`==1`表示存在有效B3快照，`==3`表示未发现有效参数快照、仅有RAM默认值。
- `Eep_Get_Record_State() == 2`表示B3记录区尚为空；旧版测量记录仍保存在`0x0000`起地址，并不等于“旧设备从未存过数据”。
- `Eep_Get_Legacy_Warnings()`: 0x01密码异常，0x02 CG异常，0x04 GJ异常，0x08 CH异常，0x10 温度格式无法可靠恢复。

这一步默认不修改EEPROM。**如芯片已有历史数据，请不要马上进行标定写入，先完成下一步外部核对。**

## 3. 人工核对旧校准并选择是否升级

使用原始备份、原检定记录和标准量具，核对GJ三点、CG左右四点及CH两个原始ADC：

- 旧代码超高/轨距温度偏移曾可能覆盖`CG_RIGHT_0_START=65523`与`GJ_1470_AD_START=65513`。
- 旧记录数量覆盖`HB_AD_START=65505`，旧索引覆盖查护温度区。
- 当前数值“看起来合理”不能证明没被旧固件覆盖；对轨道几何量测量应重新检定、必要时重新标定。

如果要把确认后的参数保存到新B3双副本区：

1. 仅在维修授权环境下，临时设置`EEP_B3_SERVICE_ENABLE_LEGACY_CAL_UPGRADE=1`。
2. 重新Rebuild和烧录。开机只在RAM中设置一次授权，不自动修改旧区。
3. 在UI中**人工完成标定并按存储键**，`Eep_Save_*`把当前完整参数快照写入`0xE000/0xE080`。
4. 重启确认状态`EEP_STATE_B3_VALID(1)`，核实每项参数及工程测量值。
5. 将服务开关改回0、重新Rebuild并保留固件版本记录。

## 4. 旧记录导入（只有确实需要才做）

由于旧版的记录数量和查护标定**物理重叠**，**绝不能直接信任`65505–65506`的“旧数量”**。先从64KiB备份和时间戳/历史保存记录逐条核实`n`（0～100）。

如果确认需要保留n条（n大于0）：

1. 确保B3新区没有记录，即`Eep_Get_Record_State()==EEP_RECORD_EMPTY(2)`。
2. 临时将`EEP_B3_SERVICE_IMPORT_LEGACY_COUNT`设置为确认的具体 `n`（1～100）。
3. 重编译并在维修模式下上电，固件会按确认的数量从旧`0x0000`起复制n×15字节到`0x2000`起，**读回对比后再提交新数量**。
4. 从UART2读取B3记录数量和内容与外部备份逐项核对；旧记录字节仍保留原地址。
5. 将迁移开关恢复0并重新烧录。以后所有新记录保存到新B3区。

如果旧记录中存在`0xFF`空洞、记录已被旧`AT24C512_Check`写坏、数量不能可靠确认，**不要进行自动导入**；先使用离线备份人工整理。

## 5. 出错后的处置

- `B3_Eeprom_Boot_OK==0`：I2C设备可能不响应或B3元数据损坏，保留现场镜像并停止写入。
- `EEP_STATE_B3_CORRUPT(4)` / `EEP_RECORD_CORRUPT(3)`：禁止自动清空、自动初始化。
- 写保护WP高：芯片可能应答I2C，但无法完成真实写入，B3通过回读识别失败。
- 升级过程中发生断电：重新启动，从有效A/B快照恢复；若两个副本都无效，需外部恢复。
- **刷回旧B2固件不能自动恢复B3新区域，更不保证能避免旧固件的地址覆盖问题**。

## 6. 不应在现场忽略的剩余问题

本批只修EEPROM可靠性和应用参数持久化。`CG_Data_Init()`是否被正确调用、查护实时测量、故障告警UI、现场检定及长时间压力测试必须另行验收。

**B3源码和电脑端测试通过，不代表已有设备历史参数已被自动修复，也不代表其轨距/超高精度已经合格。**
