# CG37 TEST 标定实时 AD 显示

2026-11-23，主控基于 CG36 TEST，配套 CG34 倾角板。

## 烧录

主控文件位于 firmware/CG37_TEST_20261123/STM32L151_CG37_TEST.hex。
已烧录 CG34 倾角板的样机，本次更新主控即可。主控开机页显示 CG37 TEST。

## 标定页面

四个采集位置的页面按四行显示。

| 行 | 显示内容 | 说明 |
| --- | --- | --- |
| 第一行 | 水平处、水平处掉头、180 mm、180 mm 掉头 | 当前采集位置 |
| 第二行 | AD:+12345 | 实时 AD，即主控最近收到的 CG_Ad |
| 第三行，采集前 | 存储键保存 | 等待 READY 后按存储键采集 |
| 第三行，采集后 | SAVE:+12340 | 本点实际采集的十帧均值 |
| 第四行 | READY、WAIT AD、WAIT DRFT 等，或 SAVED | 判稳原因与采集状态 |

实时 AD 在等待、READY 和 SAVED 页面持续更新，最后确认保存及成功页面也可观察当前 AD。传感器链路超时后显示 AD:------。

CG34 引入稳定采集时，原来已采集页面的实时 AD 被替换成了采集均值，采集提示页也未显示实时 AD。CG37 将实时值和已采集值分别明确标注，观察波动和核对取值都可直接在页面完成。

AD 的来源是倾角板滤波后经串口发给主控的值。SAVE 是本点采集均值，四点结束后需要在最终“存储键保存”画面确认，显示“成功”后完成 EEPROM 提交。

CG36 的十帧、6 AD 峰峰值、800 ms 时间下限、2 AD 前后半窗均值差判定继续用于采集。CG35 的零区间连续性算法继续用于测量。

## 测试步骤

1. 更新主控后确认开机显示 CG37 TEST，进入超高标定。
2. 在每个位置的 WAIT / READY 页面观察第二行 AD 是否随尺子变化，并在固定后观察其波动。
3. READY 时按存储键，确认第三行显示 SAVE，第二行仍能继续更新。SAVE 应保持本点采集结果，直至重新采集该点。
4. 按原步骤完成四点并最终确认“成功”，再复测水平及左右 180 mm。

## 验证

实际页面函数的主机回归通过，覆盖十个标定状态和 -32768～32767 的代表值，验证实时 AD、保存均值、五种 WAIT、READY 与通信超时占位。使用 OLED 的 128×64 尺寸和 8×16 字符宽高检查文字边界及重叠，结果通过。
原超高计算、零区间全 AD 扫描、标定保存和失败重试回归通过。Keil 全量编译为零错误、零警告。当前 Windows GCC 功能回归采用无 UBSan 的可用配置，实际 OLED 观感和设备行为需要板上确认。

实现位于 STM32L151/Software/src/App_code.c 的 CG_Calibration_Page_Reflash()，增量补丁位于 docs/patches/CG37_20261123_标定实时AD显示.patch。
