# CG34 测试版使用说明

2026-11-23

源码位于 D 盘现有 V1.0.4_B31_CG33 目录，本次测试版本名为 CG34 TEST。
本版面向水平静置波动与超高响应滞后的联合测试。整机目标由用户指定为水平误差控制在 ±0.05 mm、调整到位后两秒内稳定，结果需要实机确认。

## 烧录文件

两块板都需要烧录本次配套固件。

| 板卡 | 文件，位于 firmware/CG34_TEST_20261123 | 起始地址 |
| --- | --- | --- |
| 倾角板 STM32F103C8 | STM32F103_CG34_TEST.hex | 0x08000000 |
| 主控 STM32L151CBTxA | STM32L151_CG34_TEST.hex | 0x08000000 |

HEX 含地址信息，可由现有 Keil/ST-Link 流程加载。主控开机页显示 CG34 TEST。目录内有编译日志、功能测试记录、HEX 的 SHA-256 和源码校验清单。

## 本版行为

| 参数 | 位置 | 本版设置 |
| --- | --- | --- |
| 倾角采样目标周期 | QINGJIAOBAN/USER/main_head.h，SENSOR_SAMPLE_PERIOD_MS | 20 ms |
| 双板发包周期 | 同文件，SENSOR_SEND_PERIOD_MS | 100 ms |
| 滑动去极值平均窗口 | QINGJIAOBAN/USER/cg_angle_filter.h，CG_ANGLE_WINDOW_SIZE | 40 点，约 0.8 秒 |
| 输出更新死区 | 同文件，CG_ANGLE_DEADBAND_AD | 2 AD |
| 标定稳定窗口 | STM32L151/Software/inc/agreement_head.h | 10 帧，跨度至少 900 ms |
| 标定窗口最大波动 | 同文件，CG_CAL_STABLE_RANGE_AD | 峰峰值 3 AD |

位移传感器的 I2C 延时改为 TIM2 计时的 5 微秒等待，终止读数用 NACK，并给 ACK 采样留出建立时间。倾角优先按时采样，位移和温度以 100 ms 周期读取。这个调度会改变轨距滤波的更新节奏，实机测试时也请确认轨距跟随正常。

采样主循环在漏过完整周期后重新建立窗口，避免连续补入同一时刻的样本。TIM2 时基依据本工程 72 MHz 主时钟与 APB1 二分频配置。实际采样间隔和 I2C 波形需要板上确认。

2 AD 死区和 3 AD 标定稳定阈值为这次测试采用的初值。按默认跨度约 12446 AD 对应 180 mm，分别约为 0.029 mm 和 0.043 mm，真实换算由各仪器的标定跨度决定。

EEPROM 继续使用 B3.1 的 A/B 快照和 CRC 格式。启动从现有快照恢复标定，人工标定在最终确认后提交新快照。现有数据可跨本次升级使用。

## 测试步骤

1. 将两块板烧录配套 HEX，确认主控开机显示 CG34 TEST。
2. 固定在检定器 0 mm，待上电读数稳定后，先记录现有标定下 60 秒的最大、最小超高值。
3. 进入超高标定，按水平、水平掉头、180 mm、180 mm 掉头的顺序放置。每个取值提示页等待 READY 后按存储键。WAIT 表示数据量或稳定性还未满足条件，按键会保持当前步骤并发出提示音。
4. 采集成功后显示 SAVED 和本次实际保存的 AD 均值。再按一次存储键进入下一个取值提示页，重新放置并等待 READY。
5. 四点完成后，进入“存储键保存”画面，再按存储键，确认显示“成功”。
6. 返回 0 mm，固定 60 秒记录最大、最小值，判断是否全部在 ±0.05 mm 内。掉头重复测试，随后断电重启复测零位。
7. 做 0→30→90→180→0 mm 的变化，往返至少三次。从检定器调整到位开始计时，记录示值进入该点允许误差范围并保持稳定所用的时间，检查是否在两秒内。同步确认轨距和温度读数正常。

## 异常时记录

如果水平仍出现 −0.05 到 −0.20 mm 跳动，请记录两个示值时的 CG_Ad、CG_Value_t、CG_Value、Temp 和 CG_Param。

| 观察位置 | Watch 变量 | 用途 |
| --- | --- | --- |
| 倾角板 | CG_Angle_Filter.raw_value / filtered_value / output_value | 比较原始波动、滤波效果和发送 AD |
| 倾角板 | CG_Sample_Interval_Ms | 真实相邻采样间隔，通常应接近 20 ms |
| 倾角板 | CG_Sample_Overrun_Count | 漏过至少一个完整采样时隙的次数，应观察是否增长 |
| 主控 | CG_Calibration_Range_AD | 标定最近十帧的 AD 峰峰值 |
| 主控 | CG_Cal_Save_Failed | 0 成功，1 EEPROM，2 参数不合理，3 通信，4 未稳定 |

如果持续 WAIT，请记录 CG_Calibration_Range_AD、CG_Ad 和 Temp 的变化，再决定参数调整。连续偏移需要结合实际零点、温度和原始采样分析。

## 验证记录

双板已用本机 Keil ARMCC 5.06 update 7 build 960 全量重编译，均为零错误、零警告。
Windows GCC 功能回归通过，覆盖滤波 202 项、ADC161 7 组读码、串口和稳定采集 60 项、EEPROM 328 项，以及超高计算、保存失败重试、ACK 噪声和采样计时溢出。当前 Windows GCC 缺少 libubsan，功能测试采用其可用的编译选项运行。

理想输入的阶跃在 40 个新样本内完成滤波窗口替换。采样、实际传感器噪声、静置精度、I2C 电气时序和整机两秒内稳定待实机验证。
