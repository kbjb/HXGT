# CG32 Keil 烧录与实机验收步骤

## 第一阶段：编译烧录（两块板均需要）

1. 先把设备当前 MCU HEX 和 EEPROM 参数做离线备份；**不要擦除 AT24C512**。双板分别打开 Keil 工程：
   - 主控 `STM32L151/MDK-ARM/STM32L151.uvprojx`
   - 倾角板 `QINGJIAOBAN/PROJECT/GuiJuChi.uvprojx`
2. 两个项目各自选择 **Project → Rebuild all target files**，要求 0 error。若有警告，截图并检查是否涉及本次代码和 C99/ARMCC 兼容性。
3. 先将倾角板烧录，再将主控板烧录，确认 UART 数据链接正常。注意工程压缩包不包含本次生成的 HEX/AXF；不要使用旧 HEX。
4. 查看 EEPROM 启动 Watch：`B3_Eeprom_Boot_OK=1`、`Debug_Eep_Storage=1`、`Debug_Eep_Warnings=0`。首次新片可能进行初始化，已有 B3 有效数据应直接加载不重写。

## 第二阶段：重复性和 3000 mm 故障验证

在倾角板 Watch 添加：
- `adc161_str.ad_data`：ADC161 原始有符号 16 位值
- `CG_Angle_Filter.raw_value`：原始样本
- `CG_Angle_Filter.filtered_value`：30 点去极值平均
- `CG_Angle_Filter.output_value`、`adc161_aver`：即将串口发送的值
- `AngleParam.realValue`、`AngleParam.StableValue`：沿用旧 Watch 名称

在主控 Watch 添加：
- `CG_Ad`：主控收到的倾角 AD
- `CG_Value_t`：温度补偿前计算的超高毫米值
- `CG_Value`：主界面当前超高值
- `CG_Result_Status`：0=正常，1=坏标定，2=计算越界，3=温度异常
- `Temp`、`CG_Param`：当前温度及 EEPROM 加载的左右标定参数
- `B3_Eeprom_Boot_OK`、`Debug_Eep_Storage`：启动和标定区状态

操作：
1. 固定 0 mm、环境温度稳定，观察至少 1 分钟；记录原始 AD 的最大值、最小值，以及主界面超高数值。
2. 沿同一方向缓慢增加角度，至少经过每个曾跳到三千多的位置。重点比较原始值、滤波值和主控 `CG_Ad` 的变化是否连续。超出 ±240 mm 时现在应显示 `CG RANGE`，而不是数千毫米。
3. 再反向缓慢返回 0 mm，重复 10 次，记录每次返回的显示值。**只有稳定状态下的样本才能用于重复性评价**。
4. 放置 180 mm 标准器，静止 2 秒以上再记录；反向 180 mm 同样操作。检查正负号、固定点误差、漂移和过零连续性。
5. 如发现显示 `CAL ERROR`，先查看 `CG_Param` 四个 AD 点是否有错误；不要直接擦除 EEPROM，可通过人工标定采集正确数据后按第九步存储键提交。
6. 如果主界面只在 `CG RANGE` 时异常，继续观察底层 `adc161_str.ad_data` 是否跳过符号边界或出现固定角度突变，并使用示波器核对 ADC161 CS/CLK/OUT 的18个时钟及采样沿。

## 如何选最终的更新死区

默认：`QINGJIAOBAN/USER/cg_angle_filter.h` 内 `CG_ANGLE_DEADBAND_AD = 3`。

- 使用已完成的实际标定参数，超高每AD约为 `180 / AD跨度` mm。默认值跨度约 12446，因此每AD约 0.0145 mm。
- 3 AD 约对应 0.043 mm；4 AD 约0.058 mm；5 AD约0.072 mm。30 AD 约0.434 mm，容易造成往返滞回。
- 若固定0mm时滤波值仍经常跳动 3 AD 以上，应检查原始噪声和电源/地/布线，然后再考虑提高至4～5 AD；不要用大死区掩盖硬件不稳定。
- 本机测试不能给出最后重复性精度结论，必须基于标准器与温度试验确定。

## OLED 异常信息

`NO SENSOR`=未收到新倾角帧，`CAL ERROR`=标定参数不可信，`CG RANGE`=超高计算越界，`TEMP ERR`=温度不可信，`EEP ERR`=EEPROM校准状态非有效。显示这些内容时不可当成有效测量值。
