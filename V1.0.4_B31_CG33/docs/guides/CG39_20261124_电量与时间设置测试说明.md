# CG39 TEST 电量显示与时间设置修复

2026-11-24。基于 43b6e2f / CG38 TEST，STM32L151 主控，配套现有 CG34 TEST 倾角板。

## 固件与升级

主控文件为 `firmware/CG39_TEST_20261124/STM32L151_CG39_TEST.hex`，开机显示 CG39 TEST。已使用 CG34 TEST 倾角板的样机只更新主控。本次没有执行硬件烧录。

测量算法、查护/超高标定、EEPROM 布局及标定参数没有修改。正常升级无需因本次 UI 修复而重新标定。CG38 的查护机械方向/比例实测要求，以及相同 AD 保存后的旧固件回退兼容要求仍见 CG38 说明。

## 电量不一致的原因与修复

原 `Main_Page_Reflash()` 根据 ADC 电压和原电量换算函数选择图标，`CH_Page_Reflash()` 则直接画 `power_4_ico`，所以查护页始终显示满电。主页面还存在进入时等待下一轮定时才画图标的情况。

现在两个测量页面共同调用 `Measurement_Battery_Refresh()`，使用同一份缓存、相同图标、相同电压换算。第一次进入测量页立即采样并画图，之后切换页面立即重绘缓存，不因切换页面重复采样或显示满电。

电压采样周期统一为 5000 ms，低电量时每 500 ms 在空电池和空白图标之间切换。采样与闪烁独立，原低电量闪烁时每 500 ms 重采样的行为调整为统一的 5 s 周期；原 `Get_Driver_Power()` 的十点平均和电压分档阈值保持原值。本次统一的是显示和调度，没有重新标定电量百分比或电压模型。

修改位置为 `STM32L151/Software/src/App_code.c` 的共享电量函数，参数 `BATTERY_SAMPLE_PERIOD_MS`、`BATTERY_BLINK_PERIOD_MS` 位于该函数前。

## 时间出现几百、999 的原因

用户反馈按加减有时显示几百或 999。源码确认存在以下缺陷，能够在模拟异常数据时复现越界和残留，实机触发源尚未捕获。

- 进入页面未检查 RTC 读取返回值，读取失败时可能把未初始化的栈变量复制到编辑数组。
- 原 RTC 读取未校验 BCD、实际日期或低电压标志，异常寄存器可能被当成时间。
- 原加减仅判断“恰好等于上限”或“恰好等于零”，起始值超出范围时还会继续增减。
- `%02d` 只限定最少两位，三位数随后变回两位时没有擦除旧的第三位，可能出现拼接后的三位显示。`Set_Time` 每项是 uint8_t，单项本身只能取 0～255，不能直接存放 999。
- 月份/日期可以调到 00，也未考虑大小月和闰年；保存时 weekday 和 century 没有初始化。

## 时间设置的新操作规则

| 按键 | 操作 |
| --- | --- |
| 左键 | 当前字段减一，到下限后回到该字段上限 |
| 右键 | 当前字段加一，到上限后回到该字段下限 |
| 切换键 | 年 → 月 → 日 → 时 → 分 → 秒 → 年 |
| 确认键 | 校验并写入 RTC，成功返回菜单，失败留在页面 |
| 取消键 | 返回菜单，不保存本次编辑 |

各字段独立循环，不将秒/分的边界操作自动进位到下一字段。年月范围为 2000～2099，Y 显示后两位，顶部 `20YY` 提示世纪，例如 Y=26 表示 2026 年。

年 00～99、月 01～12、日 01～当月最后一天、时 00～23、分秒 00～59。改年或月时，若原日期不存在，会缩到新月份最后一天，例如 2026-01-31 改成 2 月为 2026-02-28，2024-02-29 改为 2025 年则变为 2025-02-28。

页面进入时检查 RTC 读取结果；加减前后和刷新时恢复异常范围，选择索引也有防越界处理。每个字段固定显示两个数字再覆盖一个空格，擦掉可能存在的旧第三位。下划线按当前实际选择重绘，不依赖中间切换状态逐个刷新。

保存时完整初始化所有 RTC 字段，weekday 根据日期计算，century 明确为 0（本工程约定 20xx）。写入前再次校验，I2C 写入返回 HAL_OK 后才返回菜单，失败提示并允许重试。本次没有新增 EEPROM 写入。

## RTC 异常提示

- `RTC READ ERROR`：通信失败、日期/BCD 不合法、RTC 低电压标志，或超出本设置页的 20xx 世纪。页面先提供 `00-01-01 00:00:00` 编辑初值，这不是当前时间，也不会自动写入；请设置全部正确字段后确认。加减后清除旧错误提示，取消可退出。
- `INVALID DATE`：确认时仍然发现非法日期/时间，不执行写入。
- `RTC WRITE ERROR`：RTC 写入返回失败，留在当前页，用户可以重试或取消。总线中途失败时 RTC 可能已写入部分数据，需重试完整设置并重新进入核对，不能视为完成。
- 两个测量页面读时钟失败时统一显示 `--/--/-- --:--`，避免显示未初始化值。通信恢复且时间有效后自动恢复显示。

驱动继续在同一笔访问中读取/写入秒到年寄存器；这是 NXP 对避免进位时读写不一致的要求。低电压标志说明时钟准确性不能保证，需重新设置时间。参考 [NXP PCF8563 数据手册](https://www.nxp.com/docs/en/data-sheet/PCF8563.pdf) 的日期时间寄存器和 Setting and reading the time 部分。

## 实机测试步骤

1. 烧录主控，确认开机 CG39 TEST。在轨距/超高与查护页来回切换，确认电量等级相同，进入就能显示图标。低电量时两页使用同一闪烁状态。
2. 进入时间设置，观察左减、右加、切换键和下划线位置。连续调整每个字段，检查始终为两位，月/日不出现 00，也不出现几百或旧第三位残留。
3. 分别检查 12 月加一到 01、01 月减一到 12、23 时加一到 00、00 时减一到 23、59 分/秒加一到 00。
4. 检查 2026 年 1 月 31 日切换到 2 月变为 28 日；2024 年 2 月可取 29 日，改为 2025 年后应收敛到 28 日。
5. 设置当前日期时间，确认返回菜单；重新进入核对，秒应继续运行。编辑后取消，再进入应读回 RTC，不能保存取消的内容。
6. 正常关机再开机检查走时。RTC READ ERROR 持续出现或断电后时间丢失时，记录现象，再检查 RTC 供电/后备电源与通信；本版未进行硬件检查。
7. 复测轨距、超高、查护显示与原标定流程。
